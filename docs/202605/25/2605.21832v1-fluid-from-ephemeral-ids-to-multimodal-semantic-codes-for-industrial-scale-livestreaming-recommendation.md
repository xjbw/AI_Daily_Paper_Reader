## 摘要
现代推荐系统高度依赖基于ID的协同过滤：每个物品由一个唯一ID嵌入表示，该嵌入从用户交互中累积协同信号。然而，直播推荐在此范式下面临独特挑战：直播间通常仅开播数十分钟，其物品ID长期处于冷启动状态，难以被充分学习，且以ID为中心的排序模型难以泛化。我们提出FLUID，这是首个在生产级直播排序器中完全摒弃候选侧物品ID的框架。FLUID将一个跨域多模态编码器（联合训练于短视频和直播，用于生成离散层次编码LUCID）与后期融合、无ID设计相结合，将切片级和直播间级LUCID作为独立token注入，并通过在线增量训练下的分阶段预热保证稳定性。该框架已部署于我们跨平台、全球总用户数超十亿的工业级直播推荐系统中，取得了显著线上收益：优质观看时长+0.55%、冷启动直播间观看量+2.05%、活跃时长+0.05%。

## Abstract
Modern recommender systems rely heavily on ID-based collaborative filtering: each item is represented by a unique ID embedding that accumulates collaborative signals from user interactions. Livestreaming recommendation, however, faces a unique challenge in this paradigm: a live room typically broadcasts for only tens of minutes, so its item ID remains poorly learned in a persistent cold-start state and ID-centric ranking models fail to generalize. We present FLUID, the first framework to fully retire the candidate-side item ID from a production-scale livestreaming ranker. FLUID couples a cross-domain multimodal encoder, jointly trained on short videos and livestreams to produce discrete hierarchical codes (LUCID), with a late-fusion, ID-free design that injects slice-level and room-level LUCID as independent tokens, stabilized by a staged warmup under online incremental training. Deployed on our industrial livestreaming recommenders with a cross-platform combined user base of over one billion globally, FLUID delivers significant online gains of +0.55% Quality Watch Duration, +2.05% Cold-Start Room Views, and +0.05% Active Hours.

## 1. 论文的核心问题与整体含义

现代推荐系统普遍以物品 ID 嵌入为核心载体，通过大规模 ID 记忆表积累协同过滤信号。然而，在**直播推荐**场景中，直播间平均存活仅约 45 分钟，**物品 ID 的协同信号在如此短暂的窗口内难以充分收敛**，导致持久的冷启动问题（如图 2 所示）。同时，现有方案虽尝试引入多模态语义信号，但大多将其作为 ID 的辅助特征，由于模型天然倾向于依赖 ID 记忆，多模态信息常被抑制，无法充分发挥作用。

FLUID 的**根本动机**在于：当物品 ID 本身就“先天不足”时，继续将其保留在候选侧只会让排序模型把大量容量浪费在已快速过时的信号上。因此，论文首次提出**在生产级直播排序中彻底废弃候选侧的物品 ID，转而以可学习的离散语义编码（LUCID）作为唯一内容标识符**，实现从“短命 ID”到“多模态语义编码”的范式转换。

## 2. 论文提出的方法论

FLUID 框架包含四个核心环节：

- **跨域多模态编码器**  
  采用 **SigLIP2-base ViT**（视觉模块）+ **Qwen3-Embedding-0.6B**（单塔融合模块）的结构。文本侧涵盖标题、OCR、ASR、作者简介、弹幕、标签等丰富元数据。模型在**短视频和直播的联合查询-物品对比任务**上训练（InfoNCE损失 + 假阴性掩蔽），使编码器从短视频密集的监督中受益，并将更稳健的视觉-文本语义迁移到直播域。

- **离散化与层次语义编码 LUCID**  
  对每 2 分钟内容切片，编码器输出 128 维向量 $z$，再经**残差量化 K-Means (RQ-KMeans)** 离散化为 $L=4$ 级、每级 $N=64$ 个码字的元组 $(c_1, c_2, c_3, c_4)$，即切片级 **LUCID**。  
  房间级 LUCID 通过对同一会话下所有切片的各级码字进行**众数投票**获得，以捕获稳定的房间身份，同时保留切片级变化。

- **前缀 n-gram LUCID 嵌入**  
  为了避免传统层级独立查表造成的码字歧义（同一码字在不同前缀下语义不同），FLUID 引入前缀组合键：
  $$
  \bar{c}_l = \sum_{k=1}^{l} c_k \cdot N^{l-k}, \quad l=1,\dots,L
  $$
  最终的 LUCID 嵌入为：
  $$
  \mathbf{e}_{\text{LUCID}} = \mathbf{E}_1(\bar{c}_1) \parallel \mathbf{E}_2(\bar{c}_2) \parallel \cdots \parallel \mathbf{E}_L(\bar{c}_L)
  $$
  切片级与房间级 LUCID 使用独立的嵌入表，以解耦瞬变动态与持久语义。

- **后期融合与分阶段预热**  
  在候选侧，FLUID 将**物品 ID 彻底移除**，仅保留两种 LUCID token 作为独立输入：
  $$
  \mathbf{T}_{\text{FLUID}} = \{\mathbf{r}, \mathbf{s}\},\quad \mathbf{g} \notin \mathbf{T}_{\text{FLUID}}
  $$
  其中 $\mathbf{r}$ 为房间级 LUCID，$\mathbf{s}$ 为切片级 LUCID。  
  为避免直接替换导致骨架坍塌，设计了**三阶段在线增量预热**：  
  1) **切片附加**：在已收敛的 ID 模型基础上，增加切片 LUCID token；  
  2) **ID 逐步退出**：渐进将物品 ID 归零，令模型转为依赖切片 LUCID；  
  3) **房间附加**：引入房间 LUCID，并将其嵌入表从已预热的切片表中初始化，独立训练。  
  该策略确保每一阶段仅改变一个候选侧组件，其余部分保持稳定锚定。

## 6. 论文的主要结论与发现

- **物品 ID 在直播场景下注定失效**：观测到 ID 嵌入范数在典型开播时长内远未收敛，冷启动问题无法通过加深融合来解决。
- **仅添加多模态特征不足以突破 ID 垄断**：早期融合或后期融合未配合分阶段训练时，模型始终倾向于 ID 记忆，LUCID 信号被严重抑制（学习出的门权重几乎全部靠向 ID）。
- **彻底移除候选侧物品 ID 是可行的且收益显著**：FLUID 最终配置在离线 AUC 上获得 **+0.23%** 提升，并在线实现 **优质观看时长+0.55%、冷启动房间观看量+2.05%、利基房间观看量+2.87%、活跃时长+0.05%** 的全面增长，且是唯一同时提升留存指标的方案。
- **切片级与房间级 LUCID 互补**：切片提供瞬时内容证据，房间提供持久身份，两者通过分阶段预热和独立嵌入表充分发挥各自作用。

## 7. 优点

- **范式突破**：敢于在十亿用户级场景中完全放弃候选侧物品 ID，而非继续修补 ID-多模态共存问题，直击直播短生命周期的根本矛盾。
- **跨域迁移训练**：利用短视频的丰富监督辅助直播编码器，有效缓解直播域内行为信号稀疏的问题，共享 LUCID 词汇表带来的语义对齐效果显著。
- **精细的嵌入设计**：前缀 n-gram 方案解决了残差量化中的路径歧义，显著优于逐级独立解码；切片/房间嵌入表分离强化了动态与静态语义的表达力。
