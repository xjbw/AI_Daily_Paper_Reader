## 摘要
GP-GOMEA是一种用于符号回归的最新进化算法，以发现小型可解释模型而闻名。然而，其计算成本仍然很高，限制了它在大规模数据集和更复杂目标表达式上的应用。相比之下，现代亚符号方法（尤其是深度学习）的兴起，很大程度上得益于GPU提供的大规模并行能力。本文首次向完全GPU加速的GP-GOMEA迈出重要一步，引入了基于GPU的适应度评估方案。我们为GP-GOMEA基于模板的个体设计了一种GPU友好的表示方式，以及相应的评估策略，充分利用了基于种群搜索的内在并行性。这大幅提高了评估吞吐量，使得在相同时间预算内能够进行数量级更多的评估。在四个标准符号回归基准测试中，这种增加的评估能力带来了性能提升，尤其是在更大数据集和更大种群规模的情况下。此外，高效评估更大数据集和更复杂模板的能力，使以前不可行的分析成为可能，让我们能够系统性地分析哪些因素使表达式对GP-GOMEA而言越来越困难，从而为表达式结构如何影响搜索难度提供了新的见解。最后，这种扩展的能力首次使与问题无关的进化算法能够在四小时内可靠地回归最大的费曼方程之一。

## Abstract
GP-GOMEA is a state-of-the-art evolutionary algorithm for symbolic regression, known for discovering small and interpretable models. However, its computational cost remains substantial, limiting its applicability to larger datasets and more complex target expressions. In contrast, the rise of modern subsymbolic approaches, particularly deep learning, has been driven largely by the massive parallelism offered by GPUs. In this work, we take the first major step toward a fully GPU-accelerated GP-GOMEA by introducing a GPU-based fitness evaluation scheme. We design a GPU-friendly representation of GP-GOMEA's template-based individuals and a corresponding evaluation strategy that exploits the inherent parallelism of population-based search. This substantially increases evaluation throughput, enabling orders of magnitude more evaluations within the same time budget. Across four standard symbolic regression benchmarks, this increased evaluation capacity yields performance improvements, particularly for larger datasets and larger population sizes. Moreover, the ability to efficiently evaluate much larger datasets and more complex templates enables analyses that were previously infeasible, allowing us to systematically analyze what makes expressions increasingly difficult for GP-GOMEA, providing new insights into how expression structure affects search difficulty. Finally, for the first time, this expanded capability allows a problem-agnostic evolutionary algorithm to reliably regress one of the largest Feynman equations within four hours.

*   **研究动机**：与依赖 GPU 并行计算而蓬勃发展的深度学习不同，进化计算领域对 GPU 的利用尚不充分。本文旨在借鉴 GPU 并行计算的思路，突破 GP-GOMEA 的效率瓶颈。
*   **核心问题**：如何将 GP-GOMEA 中计算密集的**适应度评估环节**高效地卸载到 GPU 上执行，以在不改变核心算法逻辑的前提下，大幅提升评估吞吐量和整体性能。

### 2. 论文提出的方法论

*   **核心思想**：重新设计 GP-GOMEA 的计算流程和数据结构，使其适应 GPU 的单指令多线程（SIMT）并行模式，将原本在 CPU 上串行执行的种群个体评估任务，转化为在 GPU 上可高度并行的批量任务。
*   **数据结构优化**：摒弃了不适合 GPU 的树状递归遍历结构，将每个个体（表达式树）通过后序遍历转换为**逆波兰表示法（RPN）**的线性数组。
    *   一个个体用两个定长数组表示：类型数组 $T[i]$ 和值数组 $V[i]$，分别存储节点类型（变量、常量、操作符）和对应的数值。
    *   所有个体的数组被拼接成种群级矩阵 $P^{\hat{T}}$ 和 $P^{\hat{V}}$，以支持高效的内存访问和索引。
*   **算法流程重构**：为解决串行版本中变异、评估、选择紧密耦合而难以并行化的问题，**反转了核心的 GOM（最优基因池混合）变异循环**。
    *   原流程：外循环遍历个体，内循环遍历 FOS（家族子集）。
    *   新流程：外循环遍历 FOS，内循环遍历种群中的所有个体，收集所有发生变异的个体形成一个**批次**。
    *   最后，调用 GPU 内核对整个批次进行**一次性的并行评估**。
*   **GPU 评估内核设计**：采用“**单线程块评估单一个体**”的策略。
    *   **避免线程束发散**：一个线程块内的所有线程共同评估同一个个体（同一个 RPN 序列），确保控制流一致。
    *   **多数据点处理**：块内每个线程循环处理多个数据点，累加局部平方误差和，最后通过 CUDA 原语（`cub::BlockReduce`）在共享内存中进行树状归约，得到该个体对全部数据的均方误差（MSE）。
    *   计算公式：$$\text{MSE}(y_{\text{pred}}, y_{\text{target}}) = \frac{1}{N} \sum_{i=1}^{N} (y_{\text{pred},i} - y_{\text{target},i})^2$$
    *   归一化的均方误差（NMSE）定义为：$$\text{NMSE}(y_{\text{pred}}, y_{\text{target}}) = \frac{\text{MSE}(y_{\text{pred}}, y_{\text{target}})}{\text{Var}(y_{\text{target}})}$$

### 6. 论文的主要结论与发现

*   **性能大幅提升**：GPU 加速显著提升了 GP-GOMEA 的评估吞吐量，在 Feynman 大数据集上比 CPU 版本**高出 600 倍**。这使得在相同时间内能进行数量级更多的搜索，尤其在大数据集上，验证误差（MSE）显著降低。
*   **首次解决复杂问题**：凭借 GPU 的加速能力，与问题无关的 GP-GOMEA 首次能够在 4 小时内，以 **78% 的成功率**可靠地回归出极其复杂的大型 Feynman 方程，这在之前是通过纯搜索方法难以实现的。
*   **表达式难度来源的新见解**：系统性分析表明，表达式难度增加的主要驱动因素不是规模变大，而是**非可交换算子（如减法、除法）的引入**，因为它们引入了操作数顺序约束，减少了全局最优解的数量。
*   **搜索策略影响**：实验三的重启策略比较发现，使用更小初始种群和更频繁重启的策略表现稍好，表明所测试的复杂问题其适应度景观可能是**高度多模态、且缺乏可利用的全局结构**的。

### 7. 优点

*   **创新性强**：首次将 GPU 加速引入 GP-GOMEA，针对其特定的固定模板结构和复杂变异机制，提出了完整的解决方案。
*   **设计精妙**：通过将树结构线性化为 RPN 表示，并反转 GOM 循环结构，巧妙地解决了 GPU 并行与复杂变异逻辑之间的兼容性问题。
*   **分析深刻**：利用 GPU 带来的新能力，不止步于性能报告，更系统地研究了表达式结构（特别是非可交换性）对搜索难度的本质影响，提供了有价值的学术洞见。
*   **实验严格**：采用了多维度对比（自身CPU版 vs GPU版，跨框架对比）、多参数扫描，并对数值精度问题有清晰的认识和处理（用 SymPy 重算），实验设计科学严谨。

### 8. 不足与局限

*   **加速范围有限**：目前只有**适应度评估**被卸载到 GPU，种群变异、联动学习（linkage learning）等环节仍在 CPU 上执行。对于小数据集，CPU 端的开销成为新瓶颈，抵消了 GPU 的加速效果，导致整体加速比有限。
*   **数值精度风险**：GPU 实现依赖**单精度算术**，在处理包含冗余子表达式等复杂结构时，可能放大舍入误差，甚至意外改善 NMSE，带来数值稳定性风险。
*   **功能支持滞后**：论文指出，一些已知能提升性能的技术（如区间线性缩放、多目标优化）尚未集成到此 GPU 版本中，导致在特定数据集上可能不如使用了这些技术的 CPU 方法（如 Operon）。
*   **对比的局限性**：尽管与 EvoGP 等框架进行了对比，但明确指出不同框架对表达式树的约束方式（深度限制 vs. 节点数限制）根本不同，使得解质量的直接对比不够公平，主要对比意义集中在评估吞吐量上。
