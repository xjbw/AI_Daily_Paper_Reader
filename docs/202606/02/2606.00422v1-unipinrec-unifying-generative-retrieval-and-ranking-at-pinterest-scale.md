## 摘要
现代推荐系统主要将检索与排序作为分离的模型进行训练，尽管两者都越来越依赖编码相同用户行为数据的大型变换器，导致参数、计算和服务成本的重复。先前的工作统一了模型架构，但未统一整个流程：输入格式、训练过程和服务堆栈仍跨阶段分散。我们提出了 UniPinRec，它在 Pinterest 实现了检索与排序的全栈统一：一种输入格式、一个模型、一个训练阶段，并部署于现有服务基础设施中。共享的变换器将用户行为序列编码为与候选无关的表示，然后通过任务特定头部分支到检索（ANN 点积）和排序（交叉注意力）。三个思路使其可行：(1) 掩码动作建模 (MAM) 消除了交错，使得权重共享时无需加倍上下文长度；(2) 混合训练样本将动作序列与信息流印象板块配对，以同时满足两个目标；(3) 跨阶段 KV 缓存共享重用了检索中的用户历史计算用于排序，相比运行两个独立模型减少了总 FLOPs。部署在 Pinterest 核心界面上，UniPinRec 带来了约 +1% 的在线参与度提升，同时将端到端服务延迟降低了 11.1%，并将 QPS 提升了 63.6%。据我们所知，这是首个在输入、模型、训练和服务全栈上实现检索与排序的统一，并部署于生产级推荐系统中。

## Abstract
Modern recommendation systems predominantly train retrieval and ranking as separate models despite both increasingly relying on large transformers encoding the same user behavior data, duplicating parameters, compute, and serving cost. Prior work unifies the model architecture but not the full pipeline: input formats, training procedures, and serving stacks remain fragmented across stages. We present UniPinRec, which achieves full-stack unification of retrieval and ranking at Pinterest: one input format, one model, one training stage, deployed within existing serving infrastructure. A shared transformer encodes the user action sequence into candidate-independent representations that branch into retrieval (ANN dot-product) and ranking (cross-attention) via task-specific heads. Three ideas make this work: (1) Masked Action Modeling (MAM) eliminates interleaving, enabling weight sharing without doubling context length; (2) Blended training examples pair action sequences with feedview impression slates to satisfy both objectives jointly; (3) Cross-stage KV cache sharing reuses user-history computation from retrieval for ranking, reducing total FLOPs versus serving two independent models. Deployed in the Pinterest core surfaces, UniPinRec delivers approximately +1% online engagement lift while cutting end-to-end serving latency by 11.1% and lifting QPS by 63.6%. To our knowledge, this is the first full-stack unification of retrieval and ranking, covering inputs, model, training and serving, deployed in a production recommendation system.

## 1. 论文的核心问题与整体含义

- **问题背景**：现代工业推荐系统（如 Pinterest）采用多级漏斗，检索（召回候选）和排序（精排）各自独立训练，但两者都依赖大型 Transformer 编码相同的用户行为序列。这导致模型参数、训练计算和在线推理算力的严重重复。
- **现有方案局限**：已有工作（HSTU、OnePiece 等）仅统一了模型架构，输入格式、训练流程、服务栈仍割裂；而端到端生成式方法（如 OneRec）虽然天然统一，却需替换整个流程，难以融入现有候选生成资源和逐阶段 A/B 测试操作。
- **本文目标**：实现“全栈统一”——统一输入格式、统一模型、统一训练、统一服务部署，使检索与排序共享一个 Transformer，在现有基础设施中以增量方式落地，同时消除冗余计算。

## 2. 方法论

### 2.1 核心思想

- 采用**单一 Transformer 编码器**处理用户动作序列，输出与候选无关的用户表示，再经由**任务特定头**分支完成检索（ANN 点积）和排序（跨候选交叉注意力）。
- 通过三项设计达成全栈统一：
  - **掩码动作建模（MAM）**：避免动作与物品交错导致的上下文加倍，保持输入格式与纯检索模型一致。
  - **混合训练样本**：每条样本同时包含用户动作历史（用于检索目标）和未来 impression slate with labels（用于排序目标）。
  - **跨阶段 KV 缓存共享**：在线推理时，检索阶段计算的用户历史 Key-Value 状态被排序阶段直接复用，避免重复编码。

### 2.2 关键技术细节

#### 输入表示与掩码动作建模
- 每个序列位置由物品嵌入与动作多重热点向量的拼接经过投影 MLP 得到隐状态。
- 训练时，对历史位置的动作向量以概率 $p_{\text{mask}}$ 随机替换为 `[MASK]` token；对未来候选位置动作始终掩码。
- 注意力模式采用 M‑FALCON 风格：过去位置做标准因果注意力；每个候选位置只能关注所有过去位置，不能相互关注，使得注意力复杂度从 $O((n+k)^2)$ 降为 $O(n^2 + nk)$，并保证候选得分彼此独立。

#### 联合训练损失
- **检索损失**：下一物品预测的采样 softmax 损失（对全量语料近似）
  $$L_{\text{item}} = \frac{1}{|H|} \sum_{t \in H} L_s(\hat{i}_{u,t}, i_{u,t+1})$$
  其中 $s(\hat{i}_{u,t}, i_c) = \lambda \cdot \hat{i}_{u,t}^\top i_c - \log Q(i_c)$，$Q(i_c)$ 为基于 count‑min sketch 的频率修正。
- **排序损失**：在所有掩码位置（包含过去和未来）上，对每个动作类型 $c$ 预测二值概率，使用加权二元交叉熵
  $$L_{\text{action}} = \sum_{c=1}^C w_c \left[ \frac{1}{|\mathcal{M}_{\text{past}}|}\sum_{i\in\mathcal{M}_{\text{past}}} \ell_{\text{BCE}} \big(h_{\psi_c}(z_i), a^{(c)}_i\big) + \frac{1}{k}\sum_{j=1}^k \ell_{\text{BCE}} \big(h_{\psi_c}(z_j'), a'^{(c)}_j\big) \right]$$
- 总损失：$L = L_{\text{item}} + L_{\text{action}}$。

#### 数据基础设施
- 构建**以 feedview 为中心的数据集**：将用户历史正反馈序列与该用户后续一次请求的完整 impression slate 配对，同时包含点击、保存、隐藏、无动作等标签。
- 通过** Ray 内联 Join** 在线组合两套 Iceberg 表（用户行为序列表与 feedview 表），避免离线数据膨胀，使上下文长度、采样比例成为运行时超参数。

#### 在线服务与 KV 缓存共享
- 检索与排序作为独立 Triton 模型进程，在 ANN（Faiss）完成检索后，排序节点接收候选集与 KV 缓存槽标识。
- 排序仅对候选 tokens 做一次增量前向，注意力查询复用检索生成的用户历史 KV，无需重算 $O(n^2)$ 的前缀自注意力，总排序代价约 $O(nk)$。
- 通过预分配的 GPU 内存池和 CUDA IPC 句柄映射，排序进程直接读取检索进程写入的 KV 状态，避免 CPU↔GPU 数据搬运。
- 使用混合精度 FP8（E4M3 前向/E5M2 反向）以及 Transformer Engine 融合算子，进一步加速训练和推理。

## 3. 实验设计

- **数据集与场景**：Pinterest 内部生产数据，主要使用「Board More Ideas」feed 和「Notification」推送两个表面。
- **离线基准**：
  - 生产检索模型：PinRec（12 层 Transformer，仅下一物品预测）。
  - 生产排序模型：TransAct V2 + DCNv2。
  - 统一架构基线：HSTU（行动‑物品交错范式）。
  - 剥离消融：PinRec 微调（冻结物品嵌入）、UniPinRec w/o item loss（仅排序目标）。
- **评估指标**：
  - 检索：Recall@10（未来 feedview 中正交互被正确检索的比例）。
  - 排序：Hit@3（按 save 头分数排序的前 3 准确率）。

## 6. 主要结论与发现

- UniPinRec **首次在工业级推荐系统中实现了检索与排序在全栈（输入、模型、训练、服务）的统一部署**。
- 离线方面，联合训练的 UniPinRec 在 **检索 Recall@10 持平生产模型 PinRec** 的同时，**排序 Hit@3 相比生产专用排序模型提升 14.7%**，且优于仅排序训练的变体，证明联合训练带来额外增益。
- 在线方面，Board More Ideas 界面 **save 量提升 0.95%**，Notifications 推送打开率提升 0.91%（对沉默用户提升 1.72%），并带来全站正收益；**端到端服务延迟降低 11.1%**，**QPS 提升 63.6%**，完全消除了过往两模型独立部署的冗余成本。

## 7. 优点

- **全栈统一的设计理念**：从输入格式到训练再到在线服务的每个环节均实现共享，具有理论优美性和很强的系统可扩展性。
- **掩码动作建模（MAM）**：巧妙将排序监督融入动作序列，既保留纯检索模型的序列长度，又使排序头可共享骨干，且避免了泄漏未来信息。
- **跨阶段 KV 缓存复用**：显著降低排序阶段的计算量，将排序边际成本压缩到接近零，是在线效率大幅提升的关键。
- **增量式部署兼容性**：统一模型作为现有管道的即插即用替换，保留了与关键词召回、趋势召回等源的组合能力，支持逐阶段放量和独立回滚。
- **工程可复现性强**：采用 Ray 内联 Join 构建训练数据，利用 CUDA IPC 共享显存，综合使用了 Flex Attention、FP8 优化等先进工程技术。

## 8. 不足与局限

- **未完全覆盖全漏斗**：目前仅统一了检索与 L1 轻量排序，尚未替代最终 L2 ranker（因 L2 涉及分数校准、额外特征等复杂依赖）。
- **数据集范围受限**：所有实验仅在 Pinterest 两个内部产品界面上进行，未在公开推荐数据集上验证，泛化性有待外部考察。
- **训练算力信息缺失**：论文未提供训练所需的 GPU 数量、时长或总浮点运算量，读者难以评估训练成本。
- **精度与延迟的取舍**：FP8 量化导致离线指标下降 0.5%，在线由于需要积攒 batch 以满足 Transformer Engine 形状约束（前导维度须为 8 的倍数），反而引入额外延迟，最终线上实验仍使用 bf16。
- **掩码率等超参数的可能敏感性**：最优 $p_{\text{mask}}$ 为 0.2，且更高或更低会带来性能波动，表明需针对不同场景调节。
- **模型缩放仅在离线验证**：不同深度和序列长度的收益曲线未在线验证，其对延迟‑质量的权衡在真实流量下可能更复杂。
